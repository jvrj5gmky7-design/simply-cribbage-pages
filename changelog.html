2.2.95 Fix AVAudioSession main-thread hang risk

July 31, 2026

Xcode flagged 3 "AVAudioSession Hang Risk" warnings during a real on-device debug session (iPadOS 27 Beta 2) — all synchronous setActive(true) calls made directly on the main thread (configureAudioSession, appDidBecomeActive, and the webView(didFinish:) delegate). 2.2.91 Fix Mac app New Game screen content clipping

July 30, 2026

The tablet media query (min-width:700px) caps setup/settings/stats/etc. modal boxes at a percentage of viewport height tuned for iPad's fixed portrait dimensions. The Mac app's window is arbitrarily resizable and much shorter relative to its width than iPad ever is, so that same percentage left far less usable room, silently pushing content below the fold on the welcome screen, the rotating facts, and the difficulty/personalize screen.

Give the Mac target (html.mac-app) its own override using nearly the full window height instead of a fixed vh fraction, since that's the actual constraint that matters. Verified zero overflow across the welcome screen, all 40 rotating facts, and the difficulty/personalize screen; confirmed iPad is unaffected since the override only applies under the Mac-only flag.

2.2.90 Fix dead message-level default, fix fresh-install self-registration

July 30, 2026

Message level's "off for Hard/Pro" default was baked into localStorage on first boot before any difficulty was ever chosen, permanently short-circuiting the derivation on every future launch. setDifficulty() now re-derives it (unpersisted) whenever the player hasn't made an explicit choice, so it keeps adapting to difficulty until they do.

Defaulting PLAYER_NAME to "Alex" also caused a genuinely fresh install to silently register "Alex" into the recent-players list before the user typed or clicked anything, showing "or enter another name" with a pre-selected pill on an untouched device. Boot-time player-list bookkeeping now only runs when a name was actually stored.

2.2.88 Rework game-speed pacing (backlog #37)

July 30, 2026

Beta testers reported the game feels rushed even at "slow" speed. Root cause was two separate problems: several of the most-repeated pacing delays (the pause after every peg play, the post-31 reset, the discard→cut transition, the auto-discard confirm) were hardcoded and never responded to the speed setting at all; and even where the setting was applied, "slow" was just the 1x unaccelerated baseline, never actually tuned to feel patient.

Fixed both: routed the hardcoded delays through _gs() (mostly via a single fix inside the shared _scheduleAfterPeg() helper), and shifted the whole speed scale one notch more patient — {slow:1, normal:0.6, fast:0.3} → {slow:1.5, normal:1, fast:0.6}. Today's "normal" becomes the new "fast," today's "slow" becomes the new "normal," and "slow" is a genuinely new, more patient tier. Since GAME_SPEED already defaults to "slow," every new install gets this pacing by default.

2.2.87 Fix native launch-screen mismatch, Xcode 27-beta build errors

July 29, 2026

Investigating the App Launch modal jitter (backlog item 35): user found the real transition was the native iOS LaunchScreen handing off to the SwiftUI splash view, not the web-side sequence. The SwiftUI splash rendered the logo at 350pt wide vs. the native LaunchScreen's actual 398x73pt asset, and ignored the safe area where the native screen respects it — a real, measurable mismatch causing a visible pop at handoff. Fixed by rendering the logo at its natural size and scoping ignoresSafeArea() to just the black background layer, so both screens render identically.

Also fixed two build failures surfaced while testing on the just-updated Xcode (for macOS 27 Beta 2 support):

  • AppIcon.appiconset/Contents.json had every iPad icon slot mapped to a file one scale-step too large (e.g. the 1x slot fed the @2x file). Corrected the mappings and dropped the three obsolete 1x iPad entries (deployment target is iOS 18.2; no such device exists).
  • The "Copy Card Assets" postBuildScript's recursive cp of the whole assets/ tree has no declared Input Files, which newer Xcode's Run Script sandboxing now blocks (Sandbox: cp deny file-read-data). Set ENABLE_USER_SCRIPT_SANDBOXING=NO for the target rather than enumerating every asset file as an input.

2.2.72 Fix swipe-play ghost card, peg arch scaling, automation hot-toggles + UI polish

July 22, 2026
  • Discard/pegging swipe-to-play: the card element was reused (not rebuilt) by renderPlayerCards()'s pegging fast-path, so resetting its drag transform with the CSS transition still enabled produced a visible slide-back before it dimmed into "played" state. Now resets instantly (transition disabled for the whole reset-and-play step), leaving only the intended dim/collapse animation.
  • Peg arch-crossing animation (60/61 lane transition): the two-phase animation's fixed waypoint at the arch's apex never multiplied by the board's dynamic scale factor (window._bhK), unlike every other board coordinate in the file. At typical rendered sizes (_bhK ~1.73 measured live) the waypoint was off by roughly half its correct offset. Now scales correctly with the board.
  • AUTO_DEAL, AUTO_DISCARD, and AUTO_CONTINUE were only checked once, at the moment their delay timers were scheduled — toggling a setting off during the wait didn't stop the pending auto-action from firing anyway. All three now re-check their current value when the timer actually fires.
  • New Game screen: shrank the name-input box, capped the description and Fun Facts text to a comfortable reading width instead of stretching full width on iPad, and removed the card-style background so that text floats directly on the black surface like other elements.
  • Settings > Sound: renamed "Full" to "On" (the middle "Minimal" option was already removed, leaving an odd Off/Full pairing).

2.2.70 Fix peg-row's own overflow-clip boundary + stale zone-width constant

July 21, 2026

_fitPegRow() previously translated the whole active-series wrapper as a rigid unit to keep the trailing card clear of the board/row, which could drag the group's own leading boundary card too close to (or past) the previous completed group. Now caps the shift to preserve a minimum boundary gap, using the boundary card's own measured position rather than the wrapper's — and the boundary check now runs independently of whether a rightward (overflow) correction is needed at all, since the natural flex-end packing of a short trailing group could leave the boundary gap broken even when the row/board clearance was already fine.

Removed the "_preCount" FLIP settle-animation (_pegFlip/_lastSeriesKeys): it animated a newly-dimmed card from its old mid-pegging (wrapper-packed) position to its new bare-card position, but that old position was itself an artifact of flex-end packing in a mostly-empty wrapper, not a meaningful position worth animating from — this was the direct cause of a small but real "card slides into place" visual reported repeatedly.

Separately, _fitPegRow's own corrective transform was being applied with the CSS transition still active, so even a fully correct correction visibly slid into place over ~130ms. It now applies instantly (transition disabled for the whole measure-and-correct pass), eliminating that residual movement too.
